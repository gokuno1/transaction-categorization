# Transaction Categorization using Machine Learning

## Overview

This project focuses on extracting structured, meaningful information from bank transaction descriptions, which are typically messy, and ambiguous. The goal is to build a machine-learning-driven system that can:

Identify transaction types (e.g., UPI, ATM Withdrawal, ACH Debit, Card Payment).

Extract merchant names from noisy free-text descriptions.

Classify transactions into spending categories (e.g., Food, Utilities, Shopping, Travel).

Prepare high-quality training data for downstream models.

The project is inspired by concepts learned during exploration of the Auth’n’Capture book, which explains the mechanics of the payment ecosystem—debit card number systems, payment gateways, merchant acquiring systems, and settlement logic. This sparked an interest in leveraging that understanding to solve a practical FinTech problem: making sense of transaction logs using NLP.

## Data Preprocessing
### Transaction type identification:
Transaction Type Identification is the first layer of the transaction categorization preprocessing, utilized for determining the payment instrument or channel used in a given transaction description. Bank descriptions typically encode modes such as UPI, IMPS, NEFT, ACH Debit (auto-debit for EMI), Card POS, ATM Withdrawal, Wallet Transfers, or Bank Charges, but these signals are often embedded within specific pattern, partially truncated text. The identification process combines specific keyword dictionaries with regex pattern extraction and fuzzy match to isolate mode indicators, normalize textual variants, and filter out reference numbers or irrelevant metadata. This structured mode classification provides the foundation for downstream tasks — merchant extraction, spending categorization—by ensuring that each transaction is anchored to a well-defined financial channel that reflects user intent and banking rails.

### Merchant name extraction:
Merchant Name Extraction focuses on isolating the merchant or payee entity from highly unstructured transaction descriptions generated by different banking systems, payment gateways, and merchant acquirers. Unlike transaction modes, merchant names do not follow fixed patterns and often appear mixed with reference IDs, terminal numbers, location tags, and banking metadata. The extraction pipeline combines text normalization, token filtering, and domain heuristics with machine-learning methods such as NER models (BERT-based token classification) or seq2seq tagging. These models learn to identify merchant entities in contexts such as UPI payments, POS card swipes, and online transactions, even when formatting varies across banks. The resulting merchant field enables accurate category classification, spend analytics, merchant-level aggregation, and downstream financial insights.

### NER:
```
Tokens:  [UPI]  [DR]  [36619372]  [GOIBIBO]  [HOTEL]  [BOOKING]
Labels:   O      O       O        B-MERCHANT I-MERCHANT I-MERCHANT
                                  └──────────────────────────────┘
                                      Merchant span: GOIBIBO HOTEL BOOKING
```

- **BIO (Begin-Inside-Outside)** is the standard for span extraction
- Alternatives (BIOES) add complexity without benefit for single entity type
- Transformers handle BIO natively with `AutoModelForTokenClassification`

### Seq2Seq: 
```
input = "extract_merchant: DESC: UPI DR 36619372 GOIBIBO HOTEL BOOKING | AMT: 949.93 | TYPE: DR"
output = "GOIBIBO HOTEL BOOKING"
```

- T5 is trained with task prefixes ("translate:", "summarize:")
- Adding amount/type provides context (e.g., "SALARY" is not a merchant if TYPE=CR)
- Structured format helps model learn extraction pattern

## Category Classification

### Problem Characteristics
- **Input**: Normalized description + Merchant name + Amount + Transaction type
- **Output**: Category (1 of 20+ classes)
- This is a **multiclass classification** problem with **text + numerical features**

### Brief Analysis

| Approach                        | Pros                                   | Cons                            |
|---------------------------------|----------------------------------------|---------------------------------|
| **Rule-based**                  | Explainable                            | Doesn't scale to 20+ categories |
| **TF-IDF + LogisticRegression** | Simple, fast                           | Ignores semantics               |
| **BERT fine-tuning**            | Best accuracy                          | Slow inference, expensive       |
| **Text Embeddings + GBDT**      | Fast inference, handles mixed features | Needs good embeddings           |
| **LLM (zero-shot)**             | No training                            | Expensive, slow                 |

### Design Decision: **Hybrid - SentenceTransformer + LightGBM**

```

│                     Feature Engineering Pipeline                     │

├───────────────────┤   ├───────────────────┤   ├───────────────────┤
```

## Quick Start

### 1. Transaction Type Classification

```python
from transaction_categorization.preprocessing import TransactionTypeClassifier

classifier = TransactionTypeClassifier()

# Classify a transaction
result = classifier.classify("UPI/DR/46913810/PAID TO AKASH")
print(f"Type: {result.type}, Score: {result.score}")
# Output: Type: UPI, Score: 1.0
```

### 2. Training Models

```python
from transaction_categorization.models import MerchantNERTrainer, MerchantSeq2SeqTrainer
from transaction_categorization.data import TransactionDataLoader

# Load data
loader = TransactionDataLoader("path/to/training_data.csv")
df = loader.load_csv()

# Train NER model
ner_trainer = MerchantNERTrainer()
ner_trainer.train_from_dataframe(df, output_dir="./results/ner_model")

# Train Seq2Seq model
seq2seq_trainer = MerchantSeq2SeqTrainer()
seq2seq_trainer.train_from_dataframe(df, output_dir="./results/seq2seq_model")
```

### 3. Inference

```python
from transaction_categorization.models import MerchantNERPredictor, MerchantSeq2SeqPredictor

# NER prediction
ner_predictor = MerchantNERPredictor("./results/ner_model")
result = ner_predictor.predict("UPI/DR/46913810/PAID TO AMAZON ONLINE")
print(f"Merchant: {result.merchant_name}")

# Seq2Seq prediction
seq2seq_predictor = MerchantSeq2SeqPredictor("./results/seq2seq_model")
result = seq2seq_predictor.predict("POS PURCHASE AT STARBUCKS COFFEE")
print(f"Merchant: {result.merchant_name}")
```

### 4. Full Pipeline

```python
from transaction_categorization.main import TransactionCategorizationPipeline

# Initialize pipeline with trained models
pipeline = TransactionCategorizationPipeline(
    ner_model_path="./results/ner_model",
    seq2seq_model_path="./results/seq2seq_model"
)

# Process a single transaction
result = pipeline.process_transaction(
    description="UPI/DR/46913810/PAID TO AMAZON ONLINE",
    amount=1500.00,
    dr_cr="DR"
)
print(result)

# Process a DataFrame
import pandas as pd
df = pd.read_csv("transactions.csv")
result_df = pipeline.process_dataframe(df)
```

## Data Format

Training data should be a CSV file with the following columns:

| Column          | Description                  | Required    |
|-----------------|------------------------------|-------------|
| `description`   | Transaction description text | Yes         |
| `merchant_name` | Ground truth merchant name   | Yes         |
| `amount`        | Transaction amount           | For Seq2Seq |
| `dr_cr`         | Debit/Credit indicator       | For Seq2Seq |

Example:
```csv
description,merchant_name,amount,dr_cr
"UPI/DR/46913810/PAID TO AKASH/OKHDFCBANK","AKASH OKHDFCBANK",1500.00,DR
"POS PURCHASE AT STARBUCKS COFFEE","STARBUCKS COFFEE",450.00,DR
```

## Supported Transaction Types

- `UPI` - Unified Payments Interface
- `IMPS` - Immediate Payment Service
- `NEFT` - National Electronic Funds Transfer
- `RTGS` - Real Time Gross Settlement
- `ACH-DR` - Automated Clearing House Debit
- `ACH-CR` - Automated Clearing House Credit
- `NACH` - National Automated Clearing House
- `CARD` - Card transactions (POS, ATM)
- `CASH-CR` - Cash Credit
- `CASH-DR` - Cash Debit
- `EMI` - Equated Monthly Installment
- `SALARY` - Salary credits
- `TAX` - Tax payments
- `UNKNOWN` - Unclassified
